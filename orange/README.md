# Booking Ops — UI-прототип

Статический интерфейс операторской панели на Tabler. Бэкенда, бота и внешней
автоматизации нет: все действия являются локальной демонстрацией и работают
прямо в браузере или через GitHub Pages.

## Как посмотреть

Открой `index.html` локально или включи GitHub Pages:

**Settings → Pages → Deploy from branch → `main` / `/ (root)`**

## Структура

```text
assets/
  style.css       — общие стили поверх Tabler
  layout.js       — единая навигация и верхняя панель
  mock-data.js    — демо-данные клиентов, очереди и событий
  app.js          — небольшие локальные UI-взаимодействия

index.html          — дашборд
clients.html        — список клиентов
client-card.html    — карточка клиента
client-wizard.html  — добавление клиента
queue.html          — очередь записи
monitoring.html     — мониторинг по странам
notifications.html  — уведомления
logs.html           — журнал событий
settings.html       — настройки
system-status.html  — статус сервисов и резервные копии
login.html          — экран входа-заглушка
```

## Что покрывает прототип

- полный жизненный цикл клиента: «Новый» → «Требуется авторизация» →
  «Авторизован» → «Мониторинг» → «Слот найден» → «Запись» → «CAPTCHA /
  Оплата / Видео» → «Подтверждение» → «Успешно записан», включая «Ошибка» →
  «Повтор»;
- карточка клиента с общими, паспортными, контактными, визовыми, аккаунтными,
  видео-, платёжными и подтверждающими данными;
- мастер создания из четырёх шагов, авторизация, редактирование, пауза,
  смена страны и приоритета, копирование, архив, удаление, импорт и экспорт;
- независимые очереди Испании, Франции и Италии с поиском и сортировкой;
- мониторинг по странам, расширенный журнал, уведомления Telegram-канала,
  полный список системных компонентов и все группы настроек;
- локальная сохранность изменений через `localStorage`;
- экранные демо-сценарии для выбора слота, CAPTCHA, оплаты, видео, повторной
  авторизации, ошибок и восстановления из резервной копии;
- прямые действия из очереди и центра уведомлений, ведущие к нужному блоку
  карточки клиента.

Все записи помечены как демо-данные. Реальные Telegram-уведомления, браузеры,
воркеры, CAPTCHA, оплата, шифрование, роли на сервере, heartbeat, retry policy
и фактическое восстановление требуют отдельного backend-этапа. Кнопка
восстановления показывает только пользовательский сценарий без изменения
реальных данных.
